Was Tilari ist

Tilari ist ein Buchhaltungsprogramm, das Sie im Browser nutzen. Sie buchen Ausgaben, Einnahmen und Umbuchungen, hängen Belege an, blättern in Bilanz und Gewinn- und Verlustrechnung und machen den Jahresabschluss. Die Bücher leben in einer Datei oder einem Schließfach, das Sie steuern — nicht in einem Tilari-Cloud-Konto.

Sie brauchen Kitsas nicht, um Tilari zu nutzen. Sie können im Browser ein neues finnisches Unternehmensbuch anlegen und die Bücher von dort führen.

Wenn Sie bereits Desktop-Kitsas nutzen (Buchhaltung mit offenem Quellcode), öffnet und speichert diese Version dieselbe .kitsas-Datei. Die Datei kann zwischen beiden wechseln; eine spätere Tilari kann davon abweichen. Tilari ist kein Produkt von Kitsas Oy, und Kitsas Oy unterstützt es nicht.

Fangen Sie mit einem Versuch an: Tilari öffnen, Buch anlegen, Beleg buchen. Darunter steht, was das Programm tut und für wen. Die Arbeitsweisen (HTML, dieser Rechner, ein Schließfach) kommen weiter unten auf der Seite.

Warum Tilari

  • Jetzt ausprobieren: eine HTML-Datei — beim Start legen Sie ein neues Buch an.
  • Vollständig im Browser — oder als normale Web-App.
  • Berichte, in denen Sie zum Beleg durchklicken; Änderungsprotokoll in der Sitzung.
  • Jahresabschluss ist möglich. Archiv gibt es noch nicht.
  • Das Buch in Ihrer Datei oder Ihrem eigenen Schließfach (Supabase / VPS).

Was Tilari hinzufügt

Tilari ist volle Buchhaltung im Browser, kein reiner Betrachter. Für die Alltagsarbeit bringt es Dinge, die Desktop-Programme selten an derselben Stelle bündeln — nützlich auch, wenn Sie Kitsas nie genutzt haben.

  • Browser ohne Installation: eine HTML-Datei, ein lokaler Server oder ein eigenes Schließfach. Jetzt ausprobieren; Bücher am Telefon oder auf einem USB-Stick führen.
  • Zeitnavigation: Monat / Geschäftsjahr / Alle und vor/zurück in Berichten und Hauptbuch. Ein Monat nach dem anderen ist ein natürlicher Blick auf die Periode.
  • Berichte, denen Sie folgen können: Bilanz → Konto → Beleg, plus Monatsdiagramme (Umsatz, Ergebnis, Steuer).
  • Laufender Saldo im Hauptbuch — die Kontosumme Zeile für Zeile.
  • Änderungsprotokoll in der Sitzung: was Sie vor dem Speichern geändert haben.
  • Speichern, wenn Sie wollen: die Arbeit kann im Tab bleiben; Chromium kann auch die geöffnete Datei schreiben.
  • Optionales Schließfach: Ihr Supabase (im Browser verschlüsselt) oder eigener VPS — keine Tilari-Cloud.
  • Linux-, Windows- und macOS-Pakete, wenn Sie das Programm auf diesem Rechner wollen.

Wenn Sie Kitsas schon kennen: das sind Dinge, die Desktop-Kitsas nicht in derselben Form zeigt. Desktop-Kitsas bleibt die Referenz für das, was Tilari noch nicht kopiert hat (Verein und Wohnungsaktiengesellschaft, Kontenplan-Editor, Archiv). In dieser Version funktioniert dieselbe .kitsas-Datei in beiden.

Für wen

Tilari ist nützlich für jede Person, die finnische doppelte Buchhaltung selbst führen will: Freiberufler, Einzelunternehmen, kleine Kapitalgesellschaft oder Buchhalter, die einen Browser statt eines eigenen Desktop-Programms wollen. Sie brauchen keinen Kitsas-Hintergrund — ein neues Unternehmensbuch entsteht beim Start.

Es ist besonders natürlich, wenn Sie Kitsas schon kennen: dieselbe Datei, dieselben Buchungsregeln, eine Browser-Oberfläche und Tilaris eigene Sichten (Zeit, Durchklick-Berichte, Änderungsprotokoll).

Der Autor hat Tilari im eigenen Gebrauch getestet: eine finnische Osakeyhtiö (Kapitalgesellschaft, vergleichbar einer GmbH) mit relativ wenigen Belegen (typisch für Freiberufler). Große Bücher, Verein, Wohnungsaktiengesellschaft, Einzelunternehmen und andere USt-Setups wurden nicht im Alltag getestet. Die Datei öffnet sich wahrscheinlich; das Verhalten dort ist nicht garantiert. Sagen Sie Bescheid, wenn Sie Tilari in einem anderen Buch nutzen — das hilft bei der Priorität.

Funktionen anfragen

Tilari wächst danach, was wirklich genutzt wird. Wenn Sie eine Funktion vermissen (etwas Vertrautes aus Kitsas oder eine neue Idee), öffnen Sie einen Thread in GitHub Discussions. Sie brauchen keinen Kitsas-Hintergrund: sagen Sie, was die Alltagsbuchhaltung braucht.

Merken

  • Das Buch ist Ihre Datei. Speichern Sie. Tilari hält keine Cloud-Kopie für Sie, es sei denn, das Schließfach ist Ihres.
  • Eine gespeicherte .kitsas-Datei ist in dieser Version mit Desktop-Kitsas austauschbar. Beenden Sie Desktop-Kitsas, bevor Tilari denselben Pfad schreibt.
  • Ein Speichern für Desktop-Kitsas packt Anlagen in die Datei. Die interne Arbeitskopie des Schließfachs kann „mager“ sein und öffnet sich in Kitsas nicht so.
  • Fakturierung und Freigabelauf sind in dieser Version nicht enthalten.

Zwei Verarbeitungsmodi

Nutzen Sie Tilari als normale Web-App (jede Aktion ist eine Anfrage an den Server) oder arbeiten Sie lokal im Tab und speichern Sie, wenn Sie wollen. Die Oberfläche läuft immer im Browser. Wenn ein Tilari-Node-Backend verbunden ist, fragt das Öffnen:

  • In diesem Browser (Standard) — Client: SQLite läuft in diesem Tab. Der Server kann die Datei trotzdem im Schließfach speichern, interpretiert aber keine Belege.
  • Auf dem Server — Server: dieselbe Berechnung läuft im Node-Prozess. Jede Aktion geht über die API.

Ohne Node-Backend (eine HTML-Datei, diese Site, ein Supabase-Schließfach) gibt es nur In diesem Browser. Das Schließfach (wo die Datei liegt) ist nicht dasselbe wie der Verarbeitungsmodus: Sie können das Buch im Server-Schließfach halten und trotzdem im Tab verarbeiten.

In diesem Browser (Client) Auf dem Server
Vorteile Das Buch wird nur in diesem Tab interpretiert. Mehrere Tabs oder Personen können Bücher öffnen (Speichern ins Schließfach nutzt ETag-Konflikte). Sobald die Datei im Tab ist, kann die Arbeit weitergehen, wenn das Netz abbricht. Ein Node-Neustart löscht die Arbeitskopie nicht. Ein schweres Buch auf einem schwachen Telefon: SQLite wandert auf den Host. Dieselben Buchungsregeln wie im Browser. Erneutes Öffnen kann schneller sein, solange der Prozess noch eine Sitzung hat.
Nachteile Ein großes Buch auf einem schwachen Gerät kann langsam sein. Das ganze Buch wird in den Browser geladen. Ungespeicherte Änderungen leben in diesem Tab, bis Sie speichern. Ein offenes Buch pro Serverprozess. Ein zweites Öffnen ersetzt das erste — kein Mehrbenutzerbetrieb. Jede Aktion braucht das Netz. Ein Neustart löscht die Sitzung. Der Server sieht die Buchhaltung. Nicht verfügbar mit einem Supabase-Schließfach.

Für die Alltagsarbeit und ein geteiltes Schließfach: behalten Sie In diesem Browser. Auf dem Server ist für eine Bedienung auf einem privaten Host, wenn das Buch für das Gerät zu schwer ist.

Eine HTML-Datei

Dasselbe Programm als eine Datei (etwa 1,7 MB). Auf dieser Site ist sie tilari.html — hier öffnen. Sie können die Datei auch speichern und offline öffnen.

Unter dieser URL (https)

Der Browser behandelt die Seite als sicheren Kontext: die Arbeitskopie überlebt ein Neuladen, Chrome/Edge kann an Ort und Stelle speichern, und das Supabase-Schließfach funktioniert, wenn CORS diesen Origin erlaubt. Es gibt keinen Tilari-Server: kein Auf dem Server und kein Node-Buchschließfach.

Eine Datei auf dem Datenträger (USB, E-Mail)

  1. Speichern Sie tilari.html und doppelklicken Sie sie.
  2. Wählen Sie Neue Datei wählen… und eine .kitsas.
  3. Speichern mit Speichern unter… — der Browser lädt eine neue Datei herunter.

Unter file:// stirbt die Arbeitskopie meist beim Neuladen, Überschreiben an Ort und Stelle schlägt fehl, und Sie sollten der Verschlüsselung (Supabase) nicht vertrauen. Gut für eine Demo. Für echte Bücher nutzen Sie die lokale Installation oder die https-Kopie.

Server und Client auf diesem Rechner

Das übliche Setup für eine Maschine: das Tilariprogramm (AppImage, Tilari.exe, Tilari.app oder ein lokaler Server, den die Administration startet) öffnet einen Browser unter http://127.0.0.1:8000.

Server und Client im VPN

Dasselbe Programm wie auf Ihrem Rechner, auf einer Maschine im VPN (Tailscale, WireGuard, Firmen-VPN). Andere VPN-Geräte öffnen die Adresse im Browser, zum Beispiel http://100.x.x.x:8000. Eine öffentliche Website brauchen Sie nicht.

Tilari hat keine Benutzerkonten. Jede Person, die die Adresse erreicht, sieht die Bücher im Schließfach und kann darin speichern. Die VPN-Mitgliedschaft ist die Zugangskontrolle. Teilen Sie die Adresse nicht im offenen WLAN.

Für die Person, die installiert

  1. Installieren Sie Tilari auf einer Maschine, die anbleibt (NAS, Heimserver, Büro-PC).
  2. Nehmen Sie diese Maschine in dasselbe VPN wie die Nutzergeräte.
  3. Starten Sie den Server so, dass er auf der VPN-Adresse lauscht (LAN-Bindung, z. B. --lan, gibt TILARI_LAN_URL= aus).
  4. Öffnen Sie diese URL auf den anderen Geräten. Bücher liegen im Schließfach dieser Maschine; speichern Sie mit Auf den Server speichern.

Wenn zwei Personen dasselbe Buch gleichzeitig bearbeiten, kann das zweite Speichern abgelehnt werden („die Datei hat sich geändert“). Nutzen Sie dann Auf den Server speichern unter… statt die Arbeit der anderen zu überschreiben.

Auf dem Server-Verarbeitung hält ein Buch für eine Bedienung offen. Im Büro behalten Sie den Standard In diesem Browser und teilen über das Schließfach.

Eigener VPS

Ein öffentlicher Hostname und ein Anmeldetor. Der Server hält Bücher in einem Schließfach. Nutzen Sie Tilari als normale Web-App, oder verarbeiten Sie das Buch im Browser und speichern Sie ins Schließfach. Die Installation ist Sache der Administration; diese Seite ersetzt das nicht.

Welche Browser die Datei an Ort und Stelle speichern

Speichern in der Kopfzeile versucht, denselben Pfad zu schreiben, den Sie geöffnet haben. Das funktioniert nur in manchen Browsern, und nur wenn die Seite https:// oder localhost ist (nicht eine einzelne HTML-Datei).

Browser Geöffnete Datei überschreiben In der Praxis
Chrome, Edge, Opera, Brave (Windows, macOS, Linux) Ja Neue Datei wählen… verknüpft die Datei. Speichern aktualisiert sie. Ein Dropbox-Ordner funktioniert, wenn er ein echtes Verzeichnis auf der Platte ist.
Firefox Nein Die Arbeitskopie im Browser überlebt. Auf der Platte nutzen Sie Speichern unter….
Safari (Mac, iPhone, iPad) Nein Wie Firefox: eine Kopie herunterladen.
Chrome auf Android Nicht zuverlässig Öffnen Sie aus Dropbox oder Drive mit dem Android-Dokumentwähler. Speichern ist eine Kopie (Downloads oder „Speichern unter“).

Wenn der Browser nicht an Ort und Stelle schreiben kann, sagt das Menü, Sie sollen Speichern unter… nutzen. Sie können auch Originaldatei verknüpfen…, wenn die API existiert, das Buch aber ohne Schreibrecht geöffnet wurde.

Supabase als Schließfach

Sie können Bücher in einem eigenen Supabase-Projekt halten. Sie brauchen keinen Tilari-Server: öffnen Sie Tilari von einem statischen Host (oder einer lokalen Installation) und verbinden Sie das Schließfach im Browser. Die Verarbeitung bleibt In diesem Browser. Auf dem Server wird nicht angeboten.

Einmalige Einrichtung (Supabase-Konsole)

  1. Erstellen Sie ein Projekt auf supabase.com und öffnen Sie Project Settings → API.
  2. Kopieren Sie die Project URL und den anon public-Schlüssel. Fügen Sie niemals den service_role-Schlüssel in Tilari ein — der Schlüssel ist nur für ein Backend.
  3. In Storage erstellen Sie einen privaten Bucket namens tilari (kein öffentliches CDN).
  4. Storage-Richtlinien (RLS) auf diesem Bucket für das Präfix tilari/ (anon-Rolle, select / insert / update / delete).
  5. Storage CORS: der Tilari-https-Origin, Methoden GET, POST, PUT, DELETE, Header authorization, apikey, content-type, x-upsert. Eine file://-HTML-Datei funktioniert nicht zuverlässig.

Beispiel-RLS-Richtlinien:

create policy "tilari_locker_select"
  on storage.objects for select to anon
  using (bucket_id = 'tilari' and name like 'tilari/%');
create policy "tilari_locker_insert"
  on storage.objects for insert to anon
  with check (bucket_id = 'tilari' and name like 'tilari/%');
create policy "tilari_locker_update"
  on storage.objects for update to anon
  using (bucket_id = 'tilari' and name like 'tilari/%');
create policy "tilari_locker_delete"
  on storage.objects for delete to anon
  using (bucket_id = 'tilari' and name like 'tilari/%');

In Tilari verbinden

  1. Vom Server öffnen… → Eigenes Supabase.
  2. Fügen Sie Project URL, Anon-Schlüssel, Bucket (Standard tilari) und das Verschlüsselungsgeheimnis ein (mindestens 8 Zeichen). Sie können mit Erzeugen ein Geheimnis anlegen — kopieren Sie es sofort woanders hin.
  3. Verbinden. Bücher erscheinen in der Liste; speichern Sie wie sonst ins Schließfach.

Dateien werden im Browser vor dem Hochladen verschlüsselt. URL und Anon-Schlüssel öffnen den Bucket; das Geheimnis öffnet die Dateien. Ein verlorenes Geheimnis bedeutet verlorene Bücher. Die Einstellungen bleiben nur in diesem Tab; das Schließen des Tabs trennt die Verbindung.

Dropbox-Ordner und Android (Drive / Dropbox)

Desktop: gemountetes Dropbox oder Google Drive

Tilari hat keine Dropbox- oder Drive-Anmeldung. Nutzen Sie den Ordner, den der Desktop-Client auf die Platte synchronisiert.

  1. Installieren Sie Dropbox oder Google Drive so, dass das Buch ein echter Ordner auf der Maschine ist.
  2. Öffnen Sie das Buch mit Chrome oder Edge aus diesem Ordner, damit Speichern dieselbe Datei schreibt.
  3. Der Hersteller-Client lädt die neuen Bytes auf andere Geräte.

Firefox und Safari laden eine Kopie herunter: legen Sie sie selbst in den synchronisierten Ordner zurück, sonst entstehen parallele Dateien. Lassen Sie Desktop-Kitsas nicht auf demselben Pfad offen. Wenn zwei Personen gleichzeitig speichern, behält die Cloud den letzten Schreibvorgang — Tilaris Schließfach-Konfliktwarnung gilt nicht.

Android: aus Dropbox oder Drive öffnen und speichern

Das Telefon bekommt nicht dieselbe „diesen Pfad schreiben“-Verknüpfung wie Chrome am Desktop.

  • Öffnen: Neue Datei wählen… → Android-Dokumentwähler → Dropbox, Google Drive oder Dateien. Tilari liest die Bytes.
  • Speichern: Speichern unter… legt eine Kopie in Downloads oder in der Ortsauswahl des Browsers ab. Laden Sie sie von dort nach Drive oder Dropbox, oder nutzen Sie das Systemziel „Speichern unter“, wenn der Browser eines zeigt.

Wenn dasselbe Buch ständig zwischen Telefon und PC wandert, ist ein VPN-Schließfach oder Supabase weniger fehleranfällig als der Downloads-Ordner.
